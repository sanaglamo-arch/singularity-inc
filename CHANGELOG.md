### Устойчивость сейва: backup-копия спасает прогресс при повреждении основного сейва (краш во время записи) · (game v95)
- **Что:** `save()` теперь перед перезаписью основного ключа стаскивает ПРЕДЫДУЩИЙ хороший сейв в `<KEY>_bak`; `load()` при сбое основного (повреждён прерванным крашем setItem → `JSON.parse` бросает) падает на backup. Раньше повреждённый main → `load()` возвращал false → fresh state → модал наименования → «весь прогресс исчез». Теперь теряется максимум последний сейв, не весь забег. `reset()` чистит и backup.
- **Зачем:** болевая точка владельца №1 — «баланс/прогресс иногда просто исчезает». Слепой тестировщик (в OOM-окружении) дважды получил вайп к наименованию после краша/перезагрузки. Хотя чистая перезагрузка прогресс держит (замерено: version/name/committed восстанавливаются), краш ВО ВРЕМЯ записи мог оставить битый main — теперь это восстановимо.
- **Как проверено:** харнесс (2 запуска, общий профиль) — сохранил дважды (main=v3, backup=v2), отключил автосейв, ПОВРЕДИЛ main; переоткрытие → `load()` восстановил version=2/cash=2000/name=TestCo из backup, namingModal=false (НЕ вайп), и самовосстановил валидный main. Чистая перезагрузка (отдельный замер) тоже держит. Рендер 390+1280 без оверфлоу, 0 console-ошибок; только game.js (+12/-2), styles/ui не трогались, новых i18n-ключей нет.

### Онбординг: тап КУДА УГОДНО на dim-шаге выполняет подсвеченное действие (убит «мёртвый CTA») · (ui v107)
- **Что:** на форсированных hard-dim шагах (купи ноут / открой «Железо» / купи сервер) тёмная область МЕЖДУ инструкц-карточкой и спотлайтом была «мёртвой» — тап туда не делал ничего. Теперь на таких шагах весь коуч-оверлей ловит тап и выполняет единственное разрешённое действие (`target.click()`) — тап куда угодно покупает/переключает. Лёгкие шаги (клик по сфере / апгрейд клика) оставлены click-through: сфера тапается напрямую (rapid-клик через pointerdown не сломан), карточка-инструкция остаётся шорткатом (v101).

Часть — координатный промах драйвера, но мёртвая зона между actionable-областями была реальной. Теперь форсированный шаг пуленепробиваем.
- **Как проверено:** харнесс по всем шагам — laptop@company: тап по оверлею → переключает на «Железо»; laptop@hw: → покупает ноут (tut→click); server-buy@hw: → mini 0→1, tut→release; click-шаг (LIGHT): rootPE=none, сфера pointerdown → +1 клик (rapid-клик жив), карточка-шорткат +1; рендер 390+1280 без оверфлоу, 0 console-ошибок; только ui.js (+22/-9), styles не трогался, новых i18n-ключей нет.

### КРИТ-ФИКС: релиз модели сохраняется МГНОВЕННО при выпуске (не теряется в окне катсцены) · (game v94)
- **Что:** `finishTraining()` инкрементил `version`, но НЕ сохранял — сейв происходил только в колбеке многосекундной катсцены «первая модель» или со следующим автосейвом. Перезагрузка (или OOM-убитая вкладка) ВО ВРЕМЯ катсцены теряла свежий version → откат в v0, а ре-трейн заново ф137рил онбординг-модал «Первая модель выпущена». Теперь `save()` вызывается прямо в `finishTraining()` — version + закоммиченное железо + посеянные юзеры + дефолтная цена ложатся в localStorage атомарно в момент выпуска, ДО катсцены.
- **Зачем:** НЕСКОЛЬКО слепых тестировщиков сообщали «релиз модели не переживает перезагрузку» (med-high, «losing your first empire is brutal»). Хотя сейв атомарен (version/cash в одном блобе) и часть случаев — OOM-окружение, реальный временной зазор «version инкрементнут, но ещё не сохранён» был настоящим. Закрыт.
- **Как проверено:** харнесс — до finishTraining savedVersion=0; СРАЗУ после (имитируя reload до колбека катсцены) localStorage[singularity_inc_save_v2].version=1, price=40 (sweet-spot), users посеяны → релиз персистнут атомарно в момент выпуска; рендер 390+1280 без оверфлоу, 0 console-ошибок; только game.js (+7 строк, аддитивно), styles/ui не трогались, новых i18n-ключей нет.
